# Layers 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Neuer Android-only Menüpunkt „Layers": 3D-Explosionsansicht des aktuellen Device-Screens aus `uiautomator dump` + Screenshot, mit Überlappungs-Erkennung.

**Architecture:** Reine, testbare Logik im neuen Paket `layers/` (Parser, Überlappung, orthogonale Projektion). `AdbService.uiDump` liefert das XML. `ui/LayersScreen.kt` zeichnet auf einem Compose-`Canvas`; jede Baumebene ist eine zum Screen parallele Ebene, daher ist die Abbildung je Ebene exakt affin.

**Tech Stack:** Kotlin 2.0, Compose Desktop 1.6.11, JUnit via `kotlin.test`, `javax.xml` (DOM) für das Parsen. Keine neuen Abhängigkeiten.

**Spec:** `docs/superpowers/specs/2026-11-25-layers-3d-design.md`

Arbeitsbranch: `feature/layers-3d` (von `master`), Merge am Ende wie bei `feature/device-snapshots`.

## Global Constraints

- Nur Android (`platforms = setOf(Platform.Android)`); iOS-`when` in `App.kt` bekommt `Screen.Layers` in die `Unit`-Zeile.
- Keine neuen Abhängigkeiten, keine Perspektive, kein Live-Modus.
- `AdbService`-Konventionen: `suspend fun … = withContext(Dispatchers.IO)`, `Result<T>`.
- Reine Logik unter `src/main/kotlin/layers/`, Tests unter `src/test/kotlin/layers/`.
- „Überlappung" = nur geometrisch (Bounds schneiden sich mit Fläche > 0, nicht Eltern/Kind); das UI sagt das in einem Hinweis.
- Nur Nodes mit Fläche > 0 werden gezeichnet.
- README „Project Structure" und `HelpScreen` am Ende aktualisieren (CLAUDE.md).
- Gradle-Befehle: `./gradlew test`, `./gradlew build`.

## Review Focus

- Dump-Ausgabe mit Text vor/nach dem XML (`UI hierchary dumped to: /dev/tty`) → Parser muss das tolerieren (Task 1).
- Gerät liefert keinen Dump (leer, `ERROR:` …) → `Result.failure` mit lesbarer Meldung, kein Absturz (Task 4).
- Nodes mit Fläche 0 oder negativer Fläche / außerhalb des Screens → nicht gezeichnet, keine Überlappung (Tasks 2, 5).
- Mehrere hundert Nodes → Überlappungsprüfung bleibt schnell (Task 2).
- Sonderzeichen in `text` (`&amp;`, Emoji, Zeilenumbruch) → Parser behält sie korrekt (Task 1).

### Task 3: Projektion

**Files:**
- Create: `src/main/kotlin/layers/Projection.kt`
- Test: `src/test/kotlin/layers/ProjectionTest.kt`

**Interfaces:**
- Produces:
  - `data class Vec2(val x: Float, val y: Float)`
  - `class PlaneMap(val origin: Vec2, val ex: Vec2, val ey: Vec2)` mit `fun map(x: Float, y: Float): Vec2` (= `origin + x*ex + y*ey`) und `fun unmap(p: Vec2): Vec2?` (Inverse der 2×2-Matrix `[ex ey]`; `null` bei |det| < 1e-4).
  - `fun planeMap(yawDeg: Float, pitchDeg: Float, z: Float): PlaneMap` – Rotation um Y (yaw), dann um X (pitch), orthogonal auf XY: `origin = (z·sinY, −z·cosY·sinP)`, `ex = (cosY, sinY·sinP)`, `ey = (0, cosP)`.
  - `fun isFlipped(yawDeg: Float, pitchDeg: Float): Boolean` – `cosY·cosP < 0`; dann muss das Rendering die Ebenen in umgekehrter Reihenfolge zeichnen.

- [ ] **Step 1: Tests** (Toleranz 1e-4): `identity_at_zero_angles` (ex=(1,0), ey=(0,1), origin=(0,0) für z=50); `yaw_90_collapses_plane_and_shifts_by_z` (ex≈(0,0), origin.x≈z); `pitch_shifts_layers_vertically` (yaw=0, pitch=30 → origin.y = −z·sin30); `unmap_inverts_map` (yaw=25, pitch=15, Punkt (120,340)); `unmap_returns_null_when_edge_on` (yaw=90); `flipped_beyond_90_degrees` (yaw=100 → true, 80 → false).
- [ ] **Step 2:** `./gradlew test --tests "layers.ProjectionTest"` → FAIL.
- [ ] **Step 3: Implementieren** gemäß Formeln (Grad→Bogenmaß).
- [ ] **Step 4:** Tests → PASS.
